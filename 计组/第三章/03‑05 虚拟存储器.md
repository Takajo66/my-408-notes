# 03‑05 虚拟存储器
## 1. 核心概念
### 1.1 虚拟存储器产生背景
主存容量有限，无法一次性装入全部程序。虚拟存储器依靠**操作系统+硬件MMU**，把磁盘当作主存的后备；给程序员提供一个远远大于物理主存的虚拟地址空间。
> 存储层次：**主存-辅存层次**，解决**容量不足**问题；对比Cache-主存层次解决速度问题。

### 1.2 基础名词
1. **虚拟地址（逻辑地址）**：CPU执行指令生成的地址，程序员看到的地址空间。
2. **物理地址（实地址）**：主存真实单元地址，最终送到MAR访问主存。
3. **MMU（存储器管理单元）**：硬件，完成虚拟地址 → 物理地址的地址转换。
4. **页 / 页面**：虚拟内存的传输单位；虚拟页、物理页框大小相等。
    - 虚拟页：虚拟地址空间划分出来的块；
    - 页框（物理页）：物理主存划分出来的等大小块。
5. **页表**：存放在主存，记录「虚拟页号 → 物理页框号」映射关系；同时标记有效位、脏位、保护位。
    - 有效位：标记该虚拟页是否已经调入主存。有效位=1，在内存；有效位=0，缺页。
    - 脏位（修改位）：页面载入主存后有没有被修改；页面淘汰时，脏位=1需要写回磁盘。
6. **缺页中断**：访问虚拟页，有效位=0，页面不在主存。触发中断，操作系统从磁盘读入页面到主存页框，更新页表，中断返回继续执行指令。

### 1.3 三种管理方式
1. **页式虚拟存储器（408考察最多）**
    虚拟地址拆分：`虚拟页号 | 页内偏移`
    物理地址拆分：`物理页框号 | 页内偏移`
    ✅特点：页面大小固定；地址转换快；内碎片（页面内部空闲空间）。
    页内偏移，虚拟地址与物理地址**完全相同**。

2. **段式虚拟存储器**
    程序按逻辑模块分段（函数、数据段），段长不固定。
    虚拟地址：`段号 | 段内偏移`；段表记录段起始物理地址、段长。
    ✅特点：符合程序逻辑，段可以独立保护、共享；存在外碎片。

3. **段页式虚拟存储器**
    先把程序分成段，每个段内部再分页。
    虚拟地址：`段号 | 段内页号 | 页内偏移`
    ✅特点：结合段式、页式优点；需要两次查表，开销更大。

### 1.4 快表 TLB（Translation Lookaside Buffer）
页表放在主存，每次地址转换都访问一次主存，速度太慢。
TLB是高速缓存，存放**近期常用页表项**，硬件相联存储器。
- TLB命中：直接拿到物理页框号，不需要访问内存页表。
- TLB缺失：去主存查页表；如果页表有效位=0，触发缺页中断。

> 访问顺序：CPU给出虚拟地址 → 并行查TLB + 查页表（部分教材串行）
> 408做题口径：TLB是页表的高速缓存，只缓存页表项，不缓存程序数据。

### 1.5 替换算法
主存页框全部被占用，发生缺页时，需要淘汰一个旧页面。
- LRU：淘汰最近最少使用页面（408最常考）
- FIFO：先进先出；会出现**Belady异常**：增加页框数量，缺页次数反而上升
- OPT最优算法：理论最优，无法硬件实现
> Belady异常：仅FIFO会出现；LRU、OPT没有Belady异常。

### 1.6 保护与共享
- 保护位：页表项设置读/写/执行权限；访问权限非法触发保护故障。
- 页面共享：多个虚拟页号映射到**同一个物理页框**，实现代码段共享。

## 2. 原理与推导
### 2.1 页式地址转换完整流程
1. CPU生成虚拟地址，拆分为【虚拟页号，页内偏移】
2. 使用虚拟页号，并行检索TLB
    - ✅TLB命中：取出物理页框号，拼接页内偏移，生成物理地址，访问主存。
    - ❌TLB不命中：用虚拟页号访问内存里的页表
        1. 查看页表项有效位
        2. 有效位=1（页面在主存）：取出物理页框号，拼接偏移，访问主存；同时把这条页表项载入TLB
        3. 有效位=0（缺页）：触发缺页中断，OS从磁盘调入页面，更新页表，返回重执行指令

> 重要：缺页中断属于**故障**，指令执行失败后，中断处理完成需要**重新执行触发中断的那条指令**；普通IO中断是指令执行完毕后响应。

### 2.2 地址位数计算步骤
1. 页面大小 = $2^\text{页内偏移位数}$
2. 虚拟地址总位数：决定虚拟地址空间大小
3. 虚拟页号位数 = 虚拟地址总位数 − 页内偏移位数
4. 物理地址总位数：物理主存空间大小
5. 物理页框号位数 = 物理地址总位数 − 页内偏移位数

### 2.3 缺页中断特点
1. 属于内部异常，由CPU访问内存指令本身触发；
2. 中断返回后，**重新执行当前指令**；
3. 缺页中断处理流程由操作系统软件完成；
4. 缺页属于页面不在内存；TLb缺失只是页表项不在TLB，页面仍在主存，**不会触发缺页中断**。

### 2.4 Cache vs 虚拟存储器 对比（大题高频）
|项目|Cache-主存|主存-辅存（虚拟存储器）|
|---|---|---|
|层次目的|解决CPU与主存**速度差**|解决**主存容量不足**|
|管理实现|全部硬件实现|OS+MMU软硬件共同实现|
|交换单位|Cache行（块）|页面/段|
|对谁透明|对所有指令透明|对用户程序透明，操作系统可见|
|缺失名称|Cache缺失|缺页中断|

## 3. 典型题型
1. 虚拟地址、物理地址拆分；求页内偏移、虚拟页号、物理页框号位数。
2. TLB+页表联合地址转换，计算访问内存次数。
3. 判断缺页中断、TLB缺失的区别；区分故障与普通中断。
4. FIFO的Belady异常判断。
5. 页式、段式、段页式地址结构对比，碎片类型判断。
6. 虚拟存储器与Cache的对比简答。

## 4. 易错点
❌误区1：TLB缺失 = 缺页。
✅纠正：TLB只是缓存页表项；TLB缺失只代表这条页表项不在TLB，页面仍然可能在主存。**有效位=0才是缺页**。

❌误区2：缺页中断处理完成，继续执行下一条指令。
✅纠正：缺页是故障，返回后**重新执行触发缺页的那条指令**。

❌误区3：段式有内碎片，页式有外碎片。
✅纠正：**页式：内碎片；段式：外碎片**。

❌误区4：增加物理页框数，FIFO缺页次数一定下降。
✅纠正：FIFO存在Belady异常，页框增多缺页次数反而上升；LRU不存在Belady异常。

❌误区5：虚拟存储器扩大物理主存硬件容量。
✅纠正：虚拟存储器只是地址空间变大，**物理内存硬件容量不变**，磁盘充当后备存储。
