# 队列

## 一、队列的定义

队列是一种先进先出（FIFO，First In First Out）的线性表。

队列在一端插入元素，在另一端删除元素：
- 队尾：入队的一端。
- 队头：出队的一端。

例如，元素 a、b、c 依次入队，在没有其他操作干扰时，先出队的是 a。

## 二、队列的基本操作

- 初始化：建立空队列。
- 入队：在队尾插入元素。
- 出队：删除并取出队头元素。
- 取队头元素：读取队头元素，但不删除它。
- 判空：判断队列是否为空。

注意：入队和出队分别发生在不同的位置。

## 三、顺序队列

顺序队列使用数组存储队列元素，通过队头指针 front 和队尾指针 rear 记录队列位置。

课件主要采用 rear 指向队尾元素之后一个位置的约定。

采用这种约定时：
- front 通常指向当前队头元素。
- rear 指向下一个入队元素应存放的位置。
- 空队列可以用 front == rear 表示。

不同实现可能采用其他指针约定，做题时要先看清定义。

## 四、假溢出

普通顺序队列可能出现假溢出现象。

假设数组容量有限，经过多次入队和出队后，前面的数组位置已经空出来，但 rear 已经到达数组末尾。

此时，数组前方仍有空位置，却不能直接继续入队。

这称为假溢出。

本质原因：队列的逻辑空间可以继续利用，但顺序存储的指针没有自动回到数组开头。

## 五、循环队列

循环队列将数组逻辑上首尾相连，让指针到达数组末尾后可以回到开头。

课件通过模运算实现这种循环。

例如，数组容量为 5，数组下标为 0 到 4。若某个指针移动到末尾后需要继续前进，可利用：

新位置 = (当前位置 + 1) % 5

这样下标 4 的下一个位置就会回到 0。

## 六、循环队列的基本操作

以下采用课件中的约定：
- front 指向队头元素。
- rear 指向队尾元素之后的位置。
- MAXQSIZE 表示数组容量。

### 1. 初始化

将 front 和 rear 设置为相同值，表示队列为空。

课件还讨论了另一种指针约定：如果 rear 指向队尾元素，那么空队列可表示为 front = 0、rear = -1。这里的 -1 仅用于表示逻辑位置，不能当作有效数组下标访问。

### 2. 入队

在 rear 所指的位置存入新元素，再更新 rear：

rear = (rear + 1) % MAXQSIZE

入队前需要判断队列是否已满。

### 3. 出队

取出 front 所指位置的元素，再更新 front：

front = (front + 1) % MAXQSIZE

出队前需要判断队列是否为空。

### 4. 求队列长度

在 rear 指向队尾元素之后的位置的约定下：

队列长度 = (rear - front + MAXQSIZE) % MAXQSIZE

注意：该公式与“预留一个空间”的实现约定配套使用，不能脱离指针定义直接套用。

## 七、循环队列的队空与队满判断

循环队列可能遇到一个问题：

- 队空时，front == rear。
- 如果数组所有位置都存满，front 也可能再次等于 rear。

因此，仅凭 front == rear 无法同时区分队空和队满。

课件介绍了三种解决方案。

### 方法一：少用一个存储空间

将数组容量为 m 的循环队列最多存放 m-1 个元素。

队空条件：

front == rear

队满条件：

(rear + 1) % MAXQSIZE == front

优点：判断条件简单，不需要额外变量。

缺点：会牺牲一个数组空间。

### 方法二：增加标志位 tag

增加 tag 用来区分 front == rear 时的队空和队满状态。

课件的约定：
- 删除成功后，设置 tag = 0。
- 插入成功后，设置 tag = 1。
- tag = 0 且 front == rear：队空。
- tag = 1 且 front == rear：队满。

优点：可以使用全部数组空间。

缺点：必须在相关操作中正确维护标志位。

### 方法三：增加元素个数变量 num

使用 num 记录当前队列中的元素数量。

- num = 0：队空。
- num = MAXQSIZE：队满。

优点：能够直接记录当前元素数量。

缺点：每次入队和出队都必须正确更新 num。

## 八、链队列

链队列使用链表实现队列。

课件展示了带头结点的链队列，包含：
- 头指针 front。
- 尾指针 rear。
- 头结点。
- 队头数据结点。
- 队尾数据结点。

### 1. 初始化

建立头结点，并设置队头、队尾指针。

空队列时，头结点之后没有数据结点；具体指针关系需要遵循所采用的实现约定。

### 2. 入队

创建新结点，将其接到当前队尾之后，再更新队尾指针。

课件强调：链队列通常无需像固定容量的顺序队列那样判断数组是否已满，可以动态申请结点空间；但动态内存分配仍可能失败。

### 3. 出队

删除队头数据结点，并维护头指针及相关连接关系。

如果删除的是最后一个数据结点，还需要同步处理队尾指针，使空队列的状态保持正确。

## 九、顺序队列与链队列的比较

| 比较项目 | 顺序队列 | 链队列 |
|---|---|---|
| 存储方式 | 数组 | 链表 |
| 存储空间 | 连续 | 结点可离散存放 |
| 空间限制 | 受数组容量约束 | 受可用内存约束 |
| 主要问题 | 可能出现假溢出，需要循环队列等方案 | 需要管理结点和指针 |
| 入队、出队 | 通常 O(1) | 维护队头、队尾指针时通常 O(1) |

## 十、本章易错点

1. 队列是先进先出，栈是后进先出。
2. front 和 rear 的具体含义取决于实现约定。
3. 循环队列必须用模运算实现下标循环。
4. front == rear 可能同时表示队空和队满，需要额外约定区分。
5. “少用一个空间”的方案下，队列容量为 m 时，最多存放 m-1 个元素。
6. 采用链队列时，删除最后一个元素要正确维护队尾指针。
