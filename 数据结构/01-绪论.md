# 绪论

## 一、数据结构是什么

数据结构研究数据元素之间的关系，以及数据在计算机中的组织和存储方式。

学习数据结构时，遵循以下顺序：

1. 了解逻辑结构：数据元素之间是什么关系？
2. 分析存储结构：数据在内存中如何存放？
3. 学习基本操作：如何创建、查找、插入、删除和处理数据？

## 二、逻辑结构

逻辑结构关注的是数据元素之间的关系，不关心数据在物理内存中如何存放。

### 1. 集合结构
数据元素之间没有特定的组织关系。

### 2. 线性结构
数据元素之间是一对一的关系。除第一个元素外，每个元素有一个直接前驱；除最后一个元素外，每个元素有一个直接后继。

例如：线性表、栈、队列。

### 3. 树结构
数据元素之间具有一对多的层次关系。

### 4. 图结构
数据元素之间具有多对多的关系。

## 三、存储结构

### 1. 顺序存储
将数据元素按逻辑顺序存放在连续的存储空间中。

特点：
- 可以利用位置关系计算元素地址。
- 按位访问方便。
- 插入和删除时，可能需要移动大量元素。

### 2. 链式存储
通过结点中的指针将数据元素连接起来。

特点：
- 结点在内存中可以离散存放。
- 插入和删除时，通常通过修改指针完成连接关系的调整。
- 访问第 i 个元素通常需要从头遍历。

### 3. 索引存储
建立额外的索引表，通过索引查找数据的位置。

### 4. 散列存储
根据关键字，通过散列函数计算存储地址。

例如，课件举例使用：
地址 = 数据 % 30

注意：不同关键字可能计算出相同地址，这种情况称为散列冲突，具体处理方法需要后续学习。

## 四、算法时间复杂度

时间复杂度用于描述算法执行时间随输入规模增长的变化趋势，通常通过基本语句的执行次数进行分析。

### 1. 大 O 表示法

T(n) = O(f(n))

表示算法执行次数的渐近增长数量级。

分析时通常关注增长最快的主要项，忽略常数因子和低阶项。

### 2. 常见复杂度

- O(1)：常数阶
- O(log n)：对数阶
- O(n)：线性阶
- O(n log n)：线性对数阶
- O(n²)：平方阶

一般来说，在输入规模增大时，增长较慢的复杂度通常更有优势。

### 3. 加法原则

若两个连续执行的代码段复杂度分别为 O(f(n)) 和 O(g(n))，则总复杂度为：

O(max(f(n), g(n)))

例如：先执行 O(n) 的操作，再执行 O(n²) 的操作，总复杂度为 O(n²)。

### 4. 乘法原则

若一个操作需要重复执行，外层循环执行 O(f(n)) 次，内层操作执行 O(g(n)) 次，则总复杂度通常为：

O(f(n) × g(n))

例如，两个循环分别执行 n 次的嵌套循环，基本语句执行 n² 次，时间复杂度为 O(n²)。

### 5. 对数阶的识别

课件例题：

x = 2;
while (x < n/2)
    x = 2*x;

每次循环将 x 乘以 2，因此经过 k 次循环后，x 与 2^k 同数量级。

要达到 n/2，需要的循环次数与 log₂n 同数量级，所以时间复杂度为 O(log n)。

## 五、空间复杂度

空间复杂度描述算法运行过程中所需额外存储空间随输入规模变化的趋势。

课件通过循环申请空间与只申请一次空间进行比较，强调要关注空间申请的次数和空间是否累积。

需要注意：
- 循环执行 n 次，不代表空间复杂度必然为 O(n)。
- 如果每次申请的空间都会同时保留，累计空间可能随 n 增长。
- 如果反复使用同一块固定大小的空间，额外空间可能仍为 O(1)。

## 六、本章易错点

1. 逻辑结构不等于存储结构。
2. 线性表是逻辑结构；顺序表和链表是存储实现。
3. 时间复杂度不是简单统计代码行数，而是分析基本操作随输入规模的增长。
4. 嵌套循环通常需要分析内外层执行次数，不能只看循环层数。
5. 时间复杂度和空间复杂度描述的是不同资源。
